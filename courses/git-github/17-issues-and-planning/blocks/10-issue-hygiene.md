---
type: Warning
title: Issue hygiene
---

An issue is a message to a future reader who was not in the conversation. Write it so that reader can act.

- A vague title such as "broken" forces everyone to open the issue to learn anything. State the observable problem.
- A bug report without steps, expected behavior, and actual behavior is hard to reproduce. Include versions and a minimal example when they matter.
- Do not paste tokens, passwords, private keys, personal data, or full production logs into an issue. Redact secrets before posting.
- Do not report a security vulnerability in a public issue. Use the repository's security policy or private vulnerability reporting.
- Do not combine unrelated problems in one issue. Split them so each can be assigned, prioritized, and closed on its own.
- Do not close as `not planned` without a reason when the decision is not obvious. The next reader needs to know why.
- Do not use an issue as the only place for a decision that changes the code. Record the decision in the pull request or the documentation too.

Search for an existing issue before opening a new one. A duplicate splits the discussion and hides the people already working on the problem.
