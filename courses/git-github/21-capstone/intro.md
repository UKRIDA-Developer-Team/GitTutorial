This capstone is a guided project, not a new concept. You will ship one small feature in a recipe application from issue to release, using the workflow from the earlier chapters.

The examples use a repository called `team/recipes` and issue 42. Use a practice repository you control, or follow along and adapt the names. You are the author. A teammate reviews the pull request. If you work alone, ask another person or use a second account; do not remove the review requirement just to finish.

The rules are the rules from the course. Work on a branch, not `main`. Keep commits focused and tests passing. Open a pull request that links the issue. Wait for review and green checks. Merge with the team's strategy, then tag the merge commit and publish a release. The capstone is complete when the release exists, the issue is closed, and your local `main` matches `origin/main`.

The Git sandbox can practice the branch, commit, rebase, and tag steps. It cannot create a GitHub issue, review, or release, so those steps need a real practice repository.
